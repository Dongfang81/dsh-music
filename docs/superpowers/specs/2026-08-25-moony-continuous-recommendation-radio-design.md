# Moony 持续推荐电台设计

## 目标

把“推荐”从一次性向播放列表追加固定数量歌曲，改成可持续播放、批次内与会话内不重复的推荐电台。用户点击“推荐”表示放弃当前播放列表并进入新的收听意图；系统应立即换一批歌曲，并在之后无人干预地持续补充。

本设计同时阻断旧版歌手对象被转成 `[Object Object]` 后污染相似推荐的链路。

## 用户行为

### 开始或重新开始推荐

每次点击“推荐”都创建一个新的推荐会话：

1. 只有在新的 30 首已成功取得后，才原子清空原播放列表；取歌失败时原列表保持不变。
2. 新的 30 首成为完整播放列表，第一首立即开始播放。
3. 再次点击“推荐”表示当前内容也不喜欢：废弃当前批次和会话内尚未播放的内容，建立新会话并换成另一批 30 首。
4. 收藏列表完全独立，不受播放列表替换影响。

### 持续播放

- 播放列表在推荐模式下只展示当前批次，通常为 30 首。
- 自然播放结束或点击“下一首”都使游标前进；跳过的歌曲视为已经经过。
- 第 30 首结束或在最后一首点击“下一首”时，系统原子删除当前批次，换入下一批 30 首并播放第一首。
- 推荐池在每批开始后立即于后台补足，因此不是等到第 30 首才联网生成。
- 如果下一批尚未准备好，最后一首保持在列表中并停止，不回到第一首重复播放；客户端显示“正在准备下一批”，短暂轮询，准备好后自动换批继续。
- 推荐模式强制按列表顺序推进。用户主动切换随机、单曲循环等播放模式时，退出推荐模式。

### 退出推荐模式

以下用户动作代表重新接管播放列表，因此退出持续推荐：

- 搜索结果单击播放；
- 播放歌单或收藏列表；
- 手动追加或插入歌曲；
- 清空播放列表；
- 切换播放模式。

暂停、恢复、收藏、取消收藏、在当前推荐批次内跳转或删除一首歌，不退出推荐模式。

## 状态模型

播放器持久化一个可选的 `recommendationRadio` 状态：

```js
{
  active: true,
  sessionId: "radio-...",
  batchNumber: 1,
  seenTrackKeys: ["..."],
  waitingForNextBatch: false
}
```

- `sessionId` 区分每次用户点击“推荐”创建的新会话。
- `seenTrackKeys` 保存当前会话已经交付过的歌曲，跨 DSH 重启仍有效；退出推荐模式后即可丢弃。
- 当前队列本身是当前批次的持久化快照。DSH 重启后可恢复批次与无重复集合。
- 全局推荐池继续保留最近 120 首历史，用来降低新会话立刻重复的概率；“当前连续会话绝不重复”由 `seenTrackKeys` 提供强约束。

## 服务端流程

### `recommend`

1. 从推荐池事务性消费 30 首，并排除当前会话和全局近期历史中的重复项。
2. 解析第一首可播放地址。
3. 只有上述步骤成功，才调用播放器的 `startRecommendationRadio()` 原子替换整个队列。
4. 提交池事务，立即触发后台补池。
5. 返回 `mode: "recommendation-radio"`、会话 ID、批次编号和 30 首歌曲。

失败时回滚池事务，原播放列表、当前歌曲和推荐模式均保持不变。

### `next`

- 非最后一首：沿用普通切歌并记录反馈。
- 推荐批次最后一首：调用 `advanceRecommendationRadio()` 事务性取得下一批并原子替换队列。
- 池不足：返回 `preparing: true`，不调用会循环到队首的普通 `player.next()`；调度器紧急补池。
- 客户端收到 `preparing` 后按有上限的退避间隔重试，用户暂停、手动操作或退出推荐模式时取消重试。

### 手动播放操作

播放器的 `replaceAndPlay`、`playSong`、`append`、`insertNext`、`clearQueue` 和播放模式切换，在完成各自操作前统一调用 `exitRecommendationRadio()`。批次内的跳转、删除和收藏不调用退出。

## 推荐质量与防污染

1. 规范化阶段拒绝空歌手、非字符串对象强制转换结果、`[Object Object]` 等占位身份。
2. `current-similar` 只接受具有有效原始歌曲 ID、标题和至少一个非占位歌手的当前歌曲。
3. 推荐池生成时把纯探索来源限制在最多 20%；不足部分宁可由可靠偏好来源补充，也不让个性化热门或场景歌单占据主体。
4. 当前推荐会话的 `seenTrackKeys`、当前批次和全局近期 120 首都参与去重。
5. 升级后重新校验旧推荐池，丢弃身份异常的条目；本机部署时清除当前已污染的按钮推荐队列并重新生成池，收藏不变。

## 一致性与恢复

- 队列替换、推荐模式状态和索引由同一次播放器持久化写入，避免“队列已换但模式未换”。
- 推荐池的 `consume / commit / restore` 事务保持不变；任何播放器或音源错误都恢复消费的歌曲。
- DSH 在消费后、提交前退出时，推荐池沿用现有 pending 恢复机制。
- DSH 在当前批次中途重启时，恢复当前队列、索引、会话 ID 和已交付集合，不重新插入同一批。

## 界面反馈

- 推荐按钮文字保持“推荐”，不显示复杂过程状态。
- 点击后立即打开播放列表并关闭收藏、搜索结果等竞争面板。
- 成功时列表直接替换并开始播放，不增加额外确认。
- 仅在批次边界缺少下一批时，在播放列表顶部显示轻量提示“正在准备下一批…”。
- 手动操作退出推荐模式时不弹提示；界面自然回到普通播放列表行为。

## 测试范围

### 播放器单元测试

- 新推荐会话完整替换任意旧队列并播放第一首；
- 收藏不被替换；
- 批次状态与已交付歌曲持久化并恢复；
- 手动播放操作退出推荐模式，收藏和批次内跳转不退出；
- 最后一首不会循环回当前批次第一首。

### 推荐集成测试

- 每批 30 首，连续多个批次在同一会话内无重复；
- 第二批替换第一批而不是追加；
- 再次点击推荐建立新会话并完整刷新队列；
- 池不足或首曲解析失败时原队列不变；
- 边界补池成功后自动继续，失败时保持等待且不重复播放；
- 手动搜索播放后不再自动换入推荐批次。

### 质量回归测试

- 对象歌手不会产生 `[Object Object]`；
- 身份异常的当前曲不会调用相似推荐；
- 纯探索候选不超过最终池的 20%；
- 旧污染数据升级后被重新校验，收藏保持不变。
